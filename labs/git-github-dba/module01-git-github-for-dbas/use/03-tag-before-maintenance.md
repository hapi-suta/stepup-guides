# Exercise 03: Tag Before the Maintenance Window

**Duration:** 15 minutes
**Objective:** Use annotated tags as named restore points around a maintenance window, and compare "now" against a tag.
**Prerequisites:** BUILD guide 04 completed. Single node. Work as **postgres** on **pg-git-1**.

## Background

Professional habit: before any maintenance window, tag the config state. If anything goes sideways, "what changed since the window started" is one command instead of an argument.

```bash
sudo su - postgres
```

```bash
cd $PGDATA
```

## Question 1: Tag the pre-maintenance state

### Try it

```bash
git tag -a pre-maintenance-2026-08 -m "state before august maintenance window"
```

```bash
git tag
```

Expected output (yours will differ):

```
baseline-v1
pre-maintenance-2026-08
```

Name tags so they sort and explain themselves: `pre-maintenance-YYYY-MM`.

## Question 2: Do the maintenance change

The window's task: raise `maintenance_work_mem` so the REINDEX runs faster.

### Try it

```bash
psql -c "ALTER SYSTEM SET maintenance_work_mem = '128MB';"
```

```bash
git add postgresql.auto.conf
```

```bash
git commit -m "raise maintenance_work_mem for reindex window"
```

## Question 3: What changed since the window began?

### Try it

```bash
git diff pre-maintenance-2026-08
```

Expected output (yours will differ):

```
diff --git a/postgresql.auto.conf b/postgresql.auto.conf
--- a/postgresql.auto.conf
+++ b/postgresql.auto.conf
@@ -1,3 +1,4 @@
 # Do not edit this file manually!
 # It will be overwritten by the ALTER SYSTEM command.
 work_mem = '8MB'
+maintenance_work_mem = '128MB'
```

Comparing your working tree against a TAG - this is the "what did we touch tonight" report, generated instantly, suitable for pasting into the change ticket.

## Question 4: Get it all off the server

Tags do not push automatically (guide 03 lesson). Push the commit AND the tag:

### Try it

```bash
git push
```

```bash
git push origin pre-maintenance-2026-08
```

Expected output (yours will differ):

```
To github.com:YOUR_USERNAME/pg-git-1-config.git
 * [new tag]         pre-maintenance-2026-08 -> pre-maintenance-2026-08
```

## Question 5 (thought exercise)

After the window closes cleanly, would you tag again (`post-maintenance-2026-08`)? What would having BOTH tags let you do six months from now?
