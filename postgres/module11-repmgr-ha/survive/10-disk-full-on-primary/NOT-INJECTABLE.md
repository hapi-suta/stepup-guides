Not injectable: the runbook's fault is a file filling the filesystem that holds pg_wal. On the lab nodes that is the root filesystem, which the survive contract forbids filling below 1 GB free, and relocating pg_wal to a small loop device would mean stopping the primary, moving the WAL directory and symlinking it, a layout change that risks the cluster and its standbys. Tutor: have the learner create a large file in a scratch directory on a spare volume if they have one, otherwise walk the runbook from pasted df -h and ls -lhS pg_wal output.
